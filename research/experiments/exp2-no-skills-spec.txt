  What the schema contains (MariaDB 11.8):
  - Database: notes_app uses utf8mb4 with the utf8mb4_uca1400_ai_ci collation.
    Every statement uses IF NOT EXISTS, so you can run the file more than once,
    like the sample data.
  - account: an auto-increment id, plus email (unique) and display_name.
  - notebook: account_id, name and is_default. A name can appear only once per
    account.
    - One default per account: a stored column that is empty for every notebook
      except the default has a unique key on it.
    - Same account as its notes: a note's (notebook_id, account_id) must match
      its notebook's, so a note can't point to another account's notebook.
  - tag: account_id and name. A name can appear only once per account.
  - note:
    - Fields: title (up to 255 characters), body (MEDIUMTEXT, Markdown), status
      (active, archived or trashed; default active) and is_pinned.
    - Timestamps: created_at, plus updated_at, which changes on every update.
    - Two indexes:
      - One for the notebook list: notebook, status, pinned, created.
      - One for emptying the trash: account, status.
  - note_tag: the key is (note_id, tag_id), with an index on tag_id. When a note
    or tag is deleted, its tag links are deleted too, so emptying the trash
    leaves no orphan rows.

  Choices you might want to change:
  - Duplicate titles are allowed. The sample data finds notes by title per
    account, so a second note with an existing title would break a reload.
  - note_tag has no account check. The sample data inserts only (note_id, 
    tag_id), so the schema can't stop a note from getting another account's tag.
  - Pinning changes updated_at. Pin, archive and trash all count as updates. If
    "last updated" should mean edits to the title or body only, the app must set
    updated_at itself.
  - No full-text or tag-filter indexes yet. The spec lists those features for
    later.
